# octos-crucible 使用指南

octos-crucible 是一个评测 coding agent 的平台。你把自己的 agent 交给它，它会在隔离的容器里让 agent 按阶段完成一道题，每个阶段结束后用隐藏的测试打分，同时记录 agent 用了多少时间、调了多少次模型、消耗了多少 token、缓存命中了多少，并按公开价格折算出等价花销。你也可以跳过运行 agent 这一步，直接上传已经做好的产出，只让平台打分。

平台不是排行榜，也不绑定某一套题或某一种打分方式。题目以“题目包”的形式登记，打分以“打分器”的形式接入，两者都可以替换和扩充。目前的正式题目是 ARC-Bench 的 GitHub 题，打分器是 Playwright 浏览器测试。

使用平台只需要一个 GitHub 账号登录，不限次数。管理员可以封禁滥用的账号。

## 两种用法

**上传 agent，完整评测。** 这是平台的主要用法。你上传一个 agent 包（一个 zip，里面有 `agent.json` 和 `Dockerfile`），填写模型名、OpenAI 兼容的接口地址和你自己的 API key，选择题目包和运行遍数，再设一个下载密码。平台为每一遍单独开一台机器，构建你的 agent 镜像，然后依次给出每个阶段的需求，让 agent 在同一个工作目录里一路做下去。每个阶段结束时保存当时的产出并单独打分。评测完成后，你能看到每一遍、每个阶段的分数和用量，多遍时还有均值和波动；产出和日志可以用下载密码解压取回。怎么准备 agent 包见 [upload-agent.md](upload-agent.md)。

**上传产出，快速打分**（即将推出）。如果你已经用别的方式生成了产出，比如一个网站的 zip，可以直接上传，选择题目包和要对照的阶段，平台只跑这一阶段的测试，几分钟出结果。这种方式不运行 agent，所以不需要模型 key，也没有用量和花销数据。网页上已经有这个入口，但后台的打分流程还在开发中。

提交时可以在“预算上限”里设请求数、token 数或美元金额的上限，三者任选，默认不限。预算跨阶段累计，不是每个阶段重新计算；达到任一上限后，后续的模型请求会被拒绝（agent 收到 HTTP 429，错误类型为 `budget_exceeded`），已经做出的产出照常打分。

## 结果里的各项指标

评测详情页先给出一个总览，然后是“各阶段”表，最后是每一遍的明细。下面解释每一项数字从哪里来、怎么算。

**分数。** 每个阶段的分数是该阶段通过的测试数除以测试总数，例如 27/30 显示为 90.0%。一遍的总分是把所有阶段的通过数相加，再除以所有阶段的测试数之和，不是各阶段百分比的简单平均，所以测试多的阶段权重更大。只要有一个阶段没能正常打分，这一遍就不给总分，总览里会注明“几遍完整打分”。每个阶段还有一个结果标记：“全部通过”“部分未通过”都是正常计分；“部分未通过”也包括产出构建失败、应用起不来这类 agent 自身的问题，这时记为 0 分；“平台错误（不计分）”表示是打分器自己出了故障，与 agent 无关，这一阶段不计入总分。

**用时。** 每个阶段 agent 实际运行的时间，取自 GitHub Actions 的任务时间戳，不采信 agent 自己报告的时间。一遍的用时是各阶段之和，不含构建镜像和打分的时间。

**请求数。** agent 在这个阶段向模型发出的请求次数。所有模型调用都经过平台的计量代理，这个数字是代理记下的。

**token。** 输入 token 加输出 token。明细表里分开列出输入和输出。输出 token 包含推理（reasoning）token。

**缓存命中率。** 输入 token 中由模型服务商缓存直接提供的比例，即缓存命中的输入 token 除以全部输入 token。命中率越高，同样的输入花费越低，也通常意味着 agent 在构造上下文时更稳定地复用了前缀。

**等价花销。** 用计量代理记下的 token 数，按平台价格表（`config/pricing.json`）里的公开价格折算成美元。折算时把输入分成两部分：未命中缓存的输入按输入单价，命中缓存的输入按缓存单价，输出按输出单价。价格表里的单价以每百万 token 美元计，并注明了出处和抓取日期。如果你用的模型不在价格表里，或者价格尚未核实，这一栏显示“未知价格”，token 等其他数字照常显示。允许你自己填单价的功能即将推出。

需要注意的是，等价花销是一个用于横向比较的口径，不是你的实际账单。它假设你按量付费、按公开价格计费。如果你用的是包月套餐（coding plan）或者有折扣，实际支出会不同，这时等价花销只是参考，用来比较不同 agent、不同模型在同一道题上谁更省。

**多遍统计。** 运行多遍（最多 10 遍）时，总览和各阶段表显示的是“均值 ± 标准差”，标准差按样本计算（除以 n−1），下面还给出最低到最高的范围。agent 的结果通常有随机性，跑几遍看波动比只看一次更可靠。

## 当前状态

平台正在开发中。本指南描述的是已经确定的设计，其中网页提交、agent 运行、计量和加密存储已有实现；以下部分标为“即将推出”：上传产出的快速打分流程、自填模型单价、公开分数的展示页面。如果某项功能在你使用时与本文描述不符，以网页上的实际提示为准。
